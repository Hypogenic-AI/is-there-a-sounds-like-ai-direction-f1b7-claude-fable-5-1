# SV-Detect: AI-generated Text Detection with Steering Vectors (arXiv 2606.07313v2, 3 Sep 2026)

Vishnyakov & Gaintseva. 27 pages (main text p1-10, appendices A-G p13-27). All chunks read.
Page refs are PDF pages. "[unsure]" marks things the paper leaves unclear or that I read off a figure.

## Relevance in one line
Builds per-layer human-vs-AI linear directions in a frozen LM and uses them ONLY AS READOUT features
for a detector. There is NO steering / generation intervention anywhere in the paper.

## Research question (Sec 1, p1-2)
Can a stable human-vs-AI signal be found in intermediate representations of a frozen LLM, and does a
detector built from per-layer "AI-generated text directions" generalise under distribution shift
(domain, source model, attacks, polishing/rewriting, cross-benchmark)?

## Method (Sec 3, p3-4; Fig 2)
- Activations: frozen LM, hidden states H_l(x) at every layer l; MEAN-POOLED over all tokens:
  a_l(x) = (1/T) sum_t H_l(x)_t. Called "mean-pooled residual representation" in App D.1 (p16).
  Truncation at 2048 tokens (Sec 4.1, p5). Mean pooling chosen as "simple, stable, cheap"; max /
  attention-weighted / sentence-level pooling left to future work (p5).
- Three direction constructions per layer (Sec 3.3, p3-4), all unit-normalised:
  - Mean-difference: v = (mu_fake - mu_real) / ||mu_fake - mu_real||_2 (points human -> AI).
  - Logistic regression (DEFAULT): fit LR on layer activations, v = w_l / ||w_l||_2.
  - PCA: PC1 of paired differences {a_l(x_fake) - a_l(x_real)}.
- Feature per layer: cosine-style projection s_l(x) = <a_l(x), v_l> / ||a_l(x)||_2 (Sec 3.4, p4).
  Feature vector s(x) in R^L (one scalar per layer).
- Head: StandardScaler -> LogisticRegression (liblinear, L2, C=1.0, seed 42) (Sec 3.5, 4.1, p4-5).
  Head trained on the same train split used to build the directions (p5).
- Multi-direction variants (App F.4, p21): k directions per layer (one per training subset), combined
  into an orthonormal basis via QR; features L x k. "3-vec task-aware" (MIRAGE: polish/generate/
  rewrite) and "4-vec task-aware" (DetectRL: one per Multi-Domain subset).
- Explicit statement that directions are readout-only (Sec 3.3, p3): they are "representation-space
  directions of the same kind used in activation steering ... However, note that in SV-Detect they
  are used only as probing and classification features."

## Models
- Main backbone: GPT-Neo-2.7B (frozen), chosen to match prior work (p5). Layers indexed L0-L31.
- Backbone ablation (App C, p15): Qwen3-1.7B, Qwen3-1.7B-Base, gemma-3-1b-pt, gemma-3-1b-it.
- LLaMA-3.1-8B(-Instruct) for RepreGuard comparison (App G, p27); Llama-2-7b-hf on COLING (App E).

## Datasets and sizes
- DetectRL (Sec 4.1, p4): Multi-Domain (ArXiv, XSum, Writing, Review); Multi-LLM (GPT-3.5, Claude,
  PaLM-2, Llama-2); Multi-Attack (direct, prompt, paraphrase, perturbation, data-mixing). Training
  subsampled: 50 AI samples per (llm_type, data_type) combo for Multi-Domain, 200 for Multi-LLM;
  Multi-Attack 10,192 human and 10,192 AI. Evaluated on the full test split.
- MIRAGE (p4-5): DIG / SIG settings x Generate / Polish / Rewrite. Test sizes: 16,411 / 14,776 /
  15,735 (DIG) and 16,388 / 14,776 / 15,751 (SIG). Training = 500 human/machine pairs where the
  machine side is GPT-3.5-Turbo-POLISHED text ("polish-500"). "union-800" adds 150 Generate pairs
  (GPT-3.5-Turbo XSum) + 150 Rewrite pairs from Chen et al. 2024 (p21).
- PADBen: zero-shot target only; 5 sentence-pair regimes (PSA, GAD, AIT-L, IPD, DPA) (p5).
- RAID: zero-shot target (App F.5) and matched-supervision vs RepreGuard (App G; 512-pair cells).
- COLING-2025 MGT English (App E.1, p19): train 610,767 (228,922 human / 381,845 machine, 27
  generators); dev 261,758 (98,328 / 163,430); test 73,941.

## Baselines
Zero-shot: Log-Likelihood, Entropy, Rank, Log-Rank, LRR, NPR, DetectGPT, DNA-GPT, Revise-Detect,
Binoculars, Fast-DetectGPT, RADAR, GLTR, LLMDet. Supervised: RoBERTa-Base/Large, XLM-RoBERTa-
Base/Large, ImBD, DetectAnyLLM, RepreGuard (closest representation-based method).

## Metrics and headline numbers
Metrics: AUROC, AUPR, TPR@FPR=5%, balanced accuracy, MCC, F1 (p5).
- DetectRL in-distribution (Table 7, p23): AUROC 99.83-100.0, F1 98.75-100.0 across all cells.
  RoBERTa-Base is comparable in-distribution (e.g. 99.97-100.0 AUROC Multi-Domain).
- DetectRL cross-source F1 (Table 8, p24): Multi-Domain off-diagonal 75.01-97.09 (worst: Writing ->
  XSum 75.01, XSum -> Writing 75.72); Multi-LLM 86.58-99.60; Multi-Attack 91.66-99.10.
  Text claims +7-14 F1 over RoBERTa-Base on Multi-Domain (p6).
- MIRAGE (Table 9, p24), polish-500: AUROC 0.9777 / 0.9113 / 0.9105 (DIG gen/polish/rewrite) and
  0.9779 / 0.9089 / 0.9039 (SIG). 3-vec task-aware: 0.9912 / 0.9509 / 0.9503 and 0.9909 / 0.9499 /
  0.9421. DetectAnyLLM beats polish-500 on polish/rewrite (0.9297 / 0.9234 DIG).
- Cross-benchmark grand-mean AUROC (Fig 5, Tables 12-14): MIRAGE->DetectRL 0.943 (best);
  DetectRL->MIRAGE 0.894 (RoBERTa-Large 0.918 is better); MIRAGE->PADBen 0.812;
  DetectRL->PADBen 0.841. PADBen IPD task is near chance for every method (~0.50).
- RAID zero-shot TPR@5% (Table 14, p26): MIRAGE polish-500 Chat 71.4 / Non-Chat 10.2 / Overall
  40.8; DetectRL 1-vec 65.4 / 26.7 / 46.1; DetectRL 4-vec 78.9 / 33.7 / 56.3. Binoculars 72.8 overall.
  Authors: weak on base-model (Non-Chat) generators, "consistent with our training data containing
  only chat-tuned model outputs" (p22).
- Trained on RAID (Table 15, p27): SV-Detect 99.7 TPR@5%, AUROC 0.9993 at both GPT-Neo-2.7B and
  LLaMA-3.1-8B; RepreGuard 4.9 / 0.5500 (GPT-Neo) and 93.2 / 0.9634 (LLaMA-3.1-8B).
- COLING test (Tables 4-6, p20): Llama-2-7B LogReg trimmed Macro-F1 84.8 / acc 85.0 (would rank 1);
  GPT-Neo LogReg all 75.6 / 76.5. Dev AUROC 0.975 vs test AUROC 0.866 for GPT-Neo (large gap).
- Latency (Table 1, p14): 25.71 ms/text, about equal to one LM forward pass.

## Ablations (Sec 4.3, p7-8; Tables 2, 10, 11)
- Direction construction on DetectRL Multi-Domain, per-cell AUROC (Table 11, p25):
  LogReg off-diagonal 81.82-99.40; Mean-difference off-diagonal 71.93-98.14 (diag 99.06-100);
  PCA off-diagonal 50.83-92.69 (diag 91.53-96.24). Authors: mean-diff and PCA "degrade much more
  severely, with worst-case transfer often approaching chance level" (p8). Note: the mean-diff
  minimum in the table is 71.93, so "approaching chance" applies mainly to PCA [my reading].
- COLING (Tables 5-6): LogReg > Mean > PCA on accuracy/F1. Test AUROC for Mean is close to LogReg
  on GPT-Neo (0.860 vs 0.866) but lower on Llama-2-7B (0.912 vs 0.938).
- Classifier (Table 10): LR most reliable; CatBoost similar in-distribution, weaker worst-case;
  KNN (k=5) collapses to ~50 AUROC on several off-diagonal cells.
- Backbone (Table 2, p15; Fig 6a): all diagonals ~100. Worst off-diagonal AUROC: GPT-Neo 81.82,
  Qwen3-1.7B 87.49, Qwen3-1.7B-Base 94.02, Gemma3-1B-pt 86.19, Gemma3-1B-it 85.76. Base vs
  instruction-tuned variants of the same family give similar results (pt vs it; Base vs non-Base).

## STEERING / causal experiments
NONE. The direction is never added to or ablated from the residual stream during generation. No
coefficient, no steered output, no detector evaluated on steered text. The word "steering vector"
refers only to how the direction is constructed. The closest thing to a causal-flavoured analysis is
the logit lens (direction pushed through final LayerNorm + unembedding), which is still readout.
Future-work section does not propose generation steering either (p10).

## Interpretation analyses (Sec 5, p8-9; App D, p16-18)
- Layer attribution c_l = |w_l| * sigma_l (App D.1). MIRAGE: signal concentrated in final layers
  L29-31. DetectRL: distributed, peaks at L0-2 (attributed to surface lexical cues), ridge L14-18,
  secondary peak ~L21.
- Logit lens: logits_l = W_U^T LN_f(v_l); top tokens = +v (LLM-leaning), bottom = -v (human-leaning).
  - MIRAGE +v (L29-31): content-bearing, technical/formal fragments (paralleled, foreseen, behaviors,
    endeavors, utilizing); -v: punctuation-heavy fragments, closing quotes, a few proper nouns.
  - DetectRL +v (L14-18): "polished LLM-like register" (astical, TRY, ermanent, ebted); -v: colloquial
    / topical fragments (organising, Playstation, traged, adolesc, bigot).
  - Authors warn single-layer token readings are noisy; read only as cross-layer consensus (p17).
- Cross-LM consensus (App D.4, Fig 7/10, p17-18): 4 LMs, top-8 tokens pooled over last third of
  layers (L17-25 Gemma-3, L18-27 Qwen3, L21-31 GPT-Neo), 28 (LM, dataset) pairs. All four surface
  "endeavors", "utilization", "utilizing" on +v; three of four also "captivating", "cybersecurity",
  "leveraging", "optimization", "favorable", "unfavorable". -v consensus is weaker: casual discourse
  markers "anyway", "basically", "etc", "maybe", "really", "very". Summary: +v = "LLM-polished,
  formal, and abstract language"; -v = "casual, discourse-like language".
- Regex stylistic baseline (App D.3, p17; Table 3, p19): LR on counts / per-1000-char rates of
  typography (em-dash, curly quotes, ellipsis), markdown, discourse (formal connectives Moreover /
  Furthermore / Additionally / In conclusion / Overall; casual hedges kinda / sorta / tbh; inclusive
  pronouns), lexical ("utilizing", "endeavor", "showcase"; LOG CHARACTER LENGTH), prompt-leakage
  templates ("[Assistant]:" prefixes, refusal stubs), mid-word case flips.
  Regex AUROC: 75.59-81.71 on MIRAGE, 87.81-90.73 on DetectRL. Full pipeline gap: +13.3 to +23.5
  (MIRAGE), +9.3 to +12.2 (DetectRL). Highest-weight regex features overlap with logit-lens tokens
  (em-dashes, formal connectives, prompt-leakage templates).
- Per-token view (App D.5, Fig 1): rho_t = <h_l*(x_t), v_l*> (raw dot product, best-AUROC layer);
  LLM text shows localised spans of consistently positive projection.

## Confound controls
- Domain: only via cross-domain transfer matrices (train on one domain, test on another). Directions
  are NOT orthogonalised against domain; the 4-vec variant instead learns one direction per domain.
- Length: no control. Log character length is one feature inside the regex baseline only. Mean
  pooling and cosine normalisation are the only implicit length handling.
- Formality / register: no control; the authors' own interpretation is that the direction IS largely
  a formal / polished register axis, plus residual signal the regex bank does not capture.
- Assistant / chat persona: no explicit control. Indirect evidence: detectors trained on chat-model
  outputs transfer poorly to base-model generators on RAID (Non-Chat TPR@5% 10.2-33.7).
- No matched-topic or paired-prompt design for the direction itself (MIRAGE pairs are human text vs
  its GPT-3.5 polish, which is paired in content but this is not analysed as a control).

## Limitations stated (Sec 7, p10)
Depends on probe LM geometry; needs a full LM forward pass; English only; document-level score only
(no span attribution for mixed authorship); supervised, may need recalibration as generators change.
Suggests comparing to shrinkage LDA / contrastive objectives.
